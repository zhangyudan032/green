# 版本管理规范

本文档说明"狼王格林个人主页"项目的版本管理策略。

## 1. 版本号规范

采用语义化版本号（Semantic Versioning）：`MAJOR.MINOR.PATCH`

- **MAJOR（主版本号）**: 重大功能变更或架构调整
- **MINOR（次版本号）**: 新增功能或重要更新
- **PATCH（修订号）**: Bug修复和小优化

示例：`v1.2.3`

## 2. PRD文档版本管理

### 2.1 存放位置
所有PRD文档存放在：`docs/prd/`

### 2.2 命名规范
文件名格式：`vX.Y.Z-prd.md`

示例：
- `v1.0.0-prd.md` - 初始版本
- `v1.1.0-prd.md` - 第一次更新
- `v2.0.0-prd.md` - 重大版本更新

### 2.3 版本递增规则

| 场景 | 版本变化 | 示例 |
|------|---------|------|
| 初始创建 | - | v1.0.0 |
| 需求细化/补充说明 | PATCH +1 | v1.0.0 → v1.0.1 |
| 新增页面/功能模块 | MINOR +1 | v1.0.1 → v1.1.0 |
| 技术栈变更/架构调整 | MAJOR +1 | v1.1.0 → v2.0.0 |

### 2.4 PRD文档结构

每个PRD文档应包含：
1. 文档信息（版本号、日期、状态、作者）
2. 项目概述
3. 技术架构
4. 功能需求
5. 数据结构设计
6. 开发计划
7. 待明确需求
8. 变更历史
9. 附录

## 3. 代码版本管理

### 3.1 Git提交规范

提交信息格式：`<type>(<scope>): <subject>`

**Type类型：**
- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档更新
- `style`: 代码格式调整（不影响功能）
- `refactor`: 代码重构
- `perf`: 性能优化
- `test`: 测试相关
- `chore`: 构建工具、依赖更新

**示例：**
```bash
git commit -m "feat(home): 添加基本信息展示组件"
git commit -m "fix(game): 修复图片点击事件无响应问题"
git commit -m "docs(prd): 更新v1.1.0 PRD文档"
```

### 3.2 分支策略

- `main` - 主分支，稳定版本
- `develop` - 开发分支
- `feature/*` - 功能分支
- `fix/*` - Bug修复分支

### 3.3 Git Tag规范

每个重要版本使用Tag标记：
```bash
git tag -a v1.0.0 -m "初始版本：项目框架搭建"
git tag -a v1.1.0 -m "完成首页和家庭页开发"
```

## 4. PRD与代码版本对应关系

| PRD版本 | Git Tag | 里程碑 | 说明 |
|---------|---------|--------|------|
| v1.0.0 | - | 规划阶段 | 初始PRD，技术选型和需求规划 |
| v1.1.0 | v0.1.0 | 项目初始化 | 完成项目骨架和路由配置 |
| v1.2.0 | v0.2.0 | 首页完成 | 基本信息页和家庭页开发 |
| v1.3.0 | v0.3.0 | 故事页完成 | 故事展示和游戏页开发 |
| v2.0.0 | v1.0.0 | 正式发布 | 功能完整，测试通过 |

## 5. 版本发布流程

### 5.1 PRD更新流程
1. 创建新版本PRD文档（复制上一版本）
2. 修改文档信息（版本号、日期）
3. 更新变更内容
4. 在变更历史中记录本次变更
5. 提交到Git：`git commit -m "docs(prd): 添加vX.Y.Z PRD文档"`

### 5.2 代码发布流程
1. 完成功能开发和测试
2. 更新README.md中的版本号
3. 创建Git Tag：`git tag -a vX.Y.Z -m "版本说明"`
4. 推送Tag：`git push origin vX.Y.Z`

## 6. 版本查询

### 查看所有PRD版本
```bash
ls docs/prd/
```

### 查看Git版本历史
```bash
git log --oneline --graph
```

### 查看所有Tag
```bash
git tag -l
```

## 8. 注意事项

1. **PRD版本先行**: 在开发新功能前，先更新PRD文档
2. **版本号同步**: 确保PRD版本和代码版本的对应关系清晰
3. **文档完整性**: 每次PRD更新都要填写变更历史
4. **Git提交频率**: 小步提交，每次提交只包含一个逻辑变更
5. **Tag慎重**: 只在重要里程碑打Tag，不要随意打Tag
